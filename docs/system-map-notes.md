# System map: choices made on this branch

One line per choice; the simplest option that fit was taken each time.

- Data: nodes (name, kind, known facts), edges (from, to, what, how), open points tied to a node, numbered O1, O2, … and never reused; stored on the meeting as `systemMap` in `meeting.json`.
- Kinds: exactly the four of the export format (our system, customer system, outside service, person or role).
- Model road: the questions' `wordfall-llm` worker (the configured notes model, Qwen3 4B by default), one process for both; no second model in memory.
- Cadence: the questions' tick (≥ 30 new words and ≥ 30 s), map first, then questions, so the questions see the latest open points.
- A change to My notes also makes the next tick due (still ≥ 30 s apart), so the map reacts to a note even in a lull.
- Input per run: the map as it stands, the notes, the line said just before, and only the talk since the last map run (capped at 6,000 characters).
- Answer form (v2, after research): numbered nodes (N1…) and numbered transcript lines (L1…); one change per line — `node N7: Name (kind) [also called X] [L2]`, `alias`, `known`, `flow N2 -> N7: what | how: … [L4]`, `open N2: …? [L6]`, `solved O3: … [L8]` — nodes first; every line cites its source ([Ln] or [notes]). The v1 block-per-node form let the model invent flows that only shared a word with the talk.
- GBNF grammar: built per run from what exists — node numbers (existing + 3 offered new ones), line numbers, open point numbers — so the model can only point at real things; at most 3 new nodes + 7 other lines; word-limited fields, words ≤ 20 letters, no CJK/full-width characters (the 4B model drifted into Chinese), optional last newline.
- "Me's system" is the kind word the model sees; the export writes "our system" (the others' "our ERP" made the model file customer systems as ours).
- Greedy decoding (temperature 0) and no repetition penalty for the map, so a run on the same talk gives the same map; the questions keep the helper's 0.4.
- Checks in code against the cited line instead of "some word was said somewhere": a new node's name is in its line (±2), a fact's content words mostly are (±1, five-letter stems) and its node is named nearby, a flow's two ends are both named within ±2 lines, an open point cites a question / someone unsure / the notes, a "solved" fact is in its line and shares a word with the open point; file formats and channels (CSV, PDF, CAMT, mail, API) and "Me" are never nodes; deleted names and numbers never come back.
- Entity resolution: "also called" / `alias` lines; a proper name takes over from a generic one ("our ERP" → Business Central, the old name kept as an alias); names are matched on whole words, not letters ("ERP" is not in "LagerPro"). The v1 extra "kinds" call is gone: flows can only point at numbered nodes.
- Prompt: fixed instructions and one worked example (with a "named together, but no flow" case) first, then the map, notes and the last 4 earlier lines plus the new ones, numbered.
- Questions: the map's open points ("Name: what is unknown") go into the question prompt as what good questions find out; grammar unchanged.
- Notes "before the meeting": there is no pre-meeting draft; notes typed right after Start count, since the map only runs once talk comes in.
- User edits: rename (old name kept as an alias for the model's later edits; a name another box has is refused) and delete (with its flows and open points); nothing else.
- Edits only while recording; afterwards the map is a read-only "System map" tab.
- Export: `## System map` appended below the notes Markdown (after Open questions) when the notes are written, and again on "Write the notes again"; that is what Copy as Markdown copies.
- Export labels stay literally as specified (System map, Known, Connects to, Open, the kind words) so other tools can parse them; names, facts, flows and open points are in the meeting's language.
- Export order: kinds in the listed order, nodes in the order they came up, a flow listed under the node it comes from, no blank lines inside the section.
- Picture: HTML boxes in a column per system kind plus a row of people, SVG lines under them; kinds told apart by border (bold = ours, dashed = outside, round = person), dashed line = how unknown; no colour beyond ink.
- Layout: while recording, the map sits above the notes/transcript tabs beside the questions; the page widens to 1160 px for it.
- Setting: Settings → Meetings → Draw a system map (`meetingMap`, on by default), like the questions' switch.
- The meeting thread waits for the live model's last run before writing the notes, and the final transcript pass no longer overwrites map or questions changed meanwhile.
- Replay: `wordfall --meeting … --map [--questions] [--note-at "90:text"] [--map-json f]` prints each map change and the cost of every run; `WORDFALL_MAP_RAW=1` also prints the model's raw answers.
- Last map run when a meeting stops, once the last seconds are transcribed (the meeting thread signals it), so the end of the talk isn't lost.
- Speed: the helper keeps one model context per job ("map", "questions") and only reads where a prompt differs from that job's last one (about 60 % of a map prompt is kept); greedy runs check only the likeliest token against the grammar and mask the whole vocabulary only when it is refused. Qwen3 4B map update 6.9 s → 3.6 s, Gemma 3 12B 19 s → 11 s, same answers.
- Settings: *Live help while you talk* (`meetingLiveHelp`) turns questions and map off together (no model process while recording); the two own switches sit under it.
- Test bench: `--save-transcript` / `--transcript` replay the live model on a saved transcript without speech recognition, `--llm <id>` picks the model per run; answer keys and a scorer for the test meetings are kept outside the repo.
- Live help uses the notes model chosen in Settings (no separate choice): one model to download and keep warm.
- More checks from the Qwen3 30B runs: a generic box ("webshop", "warehouse") named in the cited line or the one before turns into the proper name given there ("which system is that?" "a Shopware shop"); names with a format, channel or folder word ("shared folder", "bank statement file", "API access") or starting with a number are no boxes; a line that is itself unsure ("I'd have to look up whether…") solves nothing; a fact that only repeats its box's name is dropped; a "how" nobody said near the flow becomes "unknown".
- Model for live help (measured on the two test meetings, saved-transcript replay, greedy): Qwen3 30B-A3B is the best overall (English 31–32 points, German 13, map update ≈ 4 s, same as 4B); Gemma 3 12B is best in English (36–41) but weak in German (7) and ≈ 11 s per update; Qwen3 4B 20–28 / 8–11. The app keeps using the notes model chosen in Settings; on a Mac with 32 GB or more, Qwen3 30B is the one to pick.
- The helper drops llama.cpp's debug log level (a few lines per decoded token; an hour-long live meeting had grown `llm.log` by about 200 MB); load info, warnings and errors still go to `llm.log`.
- Precision pass after the first real meeting (61 min, German, 7 people around one laptop mic: 157 boxes, 114 of them noise, 5 real flows of 64). Each choice below is general (German and English), not tuned to that meeting:
- A "not a box" outlet: a node line may give the kind `topic`, `data or document` or `feature or process`; the code sets such a name aside (and drops it as a candidate) instead of being forced to file "Krankenstand" as a person. The set-aside list stays out of the prompt; a set-aside name proposed as a box again comes back only as a hidden candidate.
- Tighter definition of a box in the prompt (a software system/tool/service with a name or clear role, an organisation providing a service, a real person/role who does something with the systems), German and English negative examples (Krankenstand, Weihnachten, Liefertermin, Bestellnummer, Angebot, Auftragsbestätigung, Freigabe, Erinnerung), "or work passes through" removed, and a worked example with a set-aside line and lines that add nothing.
- Names ending in a number, date or amount word ("-nummer", "-termin", "-datum", "-preis", "order number", "delivery date") are data, never boxes; checked in code (the last part of a German compound says what it is).
- A person or role needs a person signal in code: a title in the name or right before it in the line ("Herrn Tobelmann"), a common first name (a few hundred German, Austrian and English ones embedded), a team or job word (Einkauf, Buchhaltung, IT, Leiter, Techniker, accounting, manager; five letters or more also as the last part of a compound, "Projektleiter"), or a name the user gave (notes, a renamed speaker).
- Candidate stage: a new box is a hidden candidate (in `candidates`, not drawn, not exported, not in the prompt; `meeting.json` without it still loads) until a later run proposes it again and one of that run's new lines names it (cited or not), a checked flow goes to it, or it is strong (in the notes, a person's first name or title, a proper name: CamelCase, "die Firma Bitwerk", "X GmbH", "a company called X", or outside German capitalised mid-sentence, or on a call a system Me names as ours: the user knows their own product).
- Candidates the new lines name (at most 6, the latest) are shown in the prompt as "said before, not on the map (no box unless the new lines show it is a system, service or person)" with their numbers, so the model can confirm one with a node line or a flow; hidden completely, the model wrote "tax advisor" once and then never again. Worded as an invitation ("a node line with its number adds it") with "said again = cited in another earlier line", it let 8 garbles and single suppliers in; shown from the earlier lines too, flows to them went from 7 to 20 unsupported in the real meeting.
- A new name must be in its cited line with endings allowed ("Herr Tobelmann" in "an Herrn Tobelmann"; such a name was refused three times).
- At most 2 new boxes drawn at once per run; hidden candidates and set-aside names only use up the 3 node lines (capping candidates too dropped "web shop" and the planned tool in favour of garbles); past 40 boxes, saying a candidate again no longer admits it, only a flow, the notes or a strong name.
- Flow ends are matched as whole words (or with an ending, or as the last part of a compound: "Dashboard" in "Einkaufsdashboard"), not on 5-letter prefixes ("Liefertermin" is no "Lieferant"); both ends within one line of the cited line, or one there and the other the only box named in the nearest line before; a "what" that is only an end's name is dropped; a flow that brings a candidate in needs a word for something moving in the cited line itself (a line is a whole speaker turn, so one line away is often another topic) (schickt, geht, importiert, liest, sends, imports, a format or channel), matched as whole words or a few verb starts ("liefert" as a word start matched "Liefertermin" and let a garble in).
- `find()` also merges names that differ only by an ending or, from five letters on, by at most one letter in five ("Lieferanten", "Varnog" for "Varnor"), when exactly one box fits; renaming still refuses only exact names.
- A flow's "what" counts as said when its words are in the line, also as the last part of a compound ("Bankdatei" for "die Bank schickt eine Datei"); "web" is a generic word, so "the web shop" becomes "Shopware shop" when that is said.
- Compact map in the prompt: every box as one line (number, name, kind, up to 3 other names) in the order they came, then facts and flows only of the boxes the new talk or the notes name, and the open points those touch.
- Tidy-up run every 10 minutes of meeting time (after that tick's map run) and once at stop before the last map run, with its own grammar and no kept context: first "same"/"different" for up to 12 pairs of boxes whose names look alike (blocked in code: edit ratio ≤ 0.4, same first 4 or last 6 letters), then one verdict per box in order (a kind of box = keep, topic / data or document / feature or process / "misheard" = drop), judged by the line each box was first said in (`said`), its facts and flows, not by the kind it has now (shown it, the model only repeated it: no change in a whole hour). It doesn't re-kind: without the talk it swapped ours and the customer's (Order portal → customer system); the map runs keep refiling systems. Merges come only from the pairs: offered "same as N#" per box, the model merged Frau Renate and Henrik into Jonas; two people with different first names are never paired. Boxes the user renamed or the notes name are never dropped or merged away; a box with a flow isn't dropped; dropped names are set aside.
- One-mic rooms: when no talk came in as system audio, the map model sees no "Me" (the mic's first voice is "Speaker 0") and the kind word is "my company's system", described as what my company builds, runs or delivers (the tool or project the meeting is about; my notes may name it), while "customer system" is what the organisation we visit already uses, even when they say "our". On a call nothing changes ("Me's system").
- Aliases after the first real meeting (the model put "ERP" on a supplier, and six later ERP flows landed on that supplier): a name that is already a candidate is that candidate, never the generic box said next to it; an alias (`alias` line, "also called", a tidy-up merge) is never another box's or candidate's name; a generic word ("ERP", "System", "Shop") goes only on a system that has no proper name yet, or with one in the same line when the box is new; a team or job word only on a person or role; a generic box still takes a proper name of its own kind, but when nobody said "also called" only one that keeps its word ("web shop" → "Shopware shop"; Outlook said next to "the ERP" took the ERP over in the replay). A tidy-up merge never joins a person and a system.
- "Also mentioned": the hidden candidates' names (not the names set aside as topics, data or features), the latest first, at most 12, go with the live map (`alsoMentioned` in `meeting-map`) and are one quiet line under it; no boxes, no lines, not in the export, nothing to click.
- Screens and photos: each run also reads the visuals added since the last one, as `[mm:ss] Screen: …` / `Photo: …` lines among the new ones (`visuals::MAP` caps); a new visual makes a run due (still ≥ 30 s apart); the notes' sentence about such lines (`llm::SHOWN`) is part of the map's instructions (always, since the instructions must not change between runs for the helper to keep them). A name on a screen counts like a name said (it can be cited, it says a candidate again); a screen's rows start like sentences, so a capital there is no proper-name signal; a screen asks nothing and is unsure of nothing (open points need a spoken question or the notes). An address ("Industriestraße 12", "Main Street") is no box and no other name: the order confirmation's letterhead became the supplier's alias in the first photo replay.
- Second real meeting (66 min, German, a product demo on a shared screen; 26 boxes, 7 of them spelling variants of 3 products, ~9 noise, 3 of 9 real flows, facts in English and German). Each choice below is general, not tuned to that meeting:
- Names heard in different ways are one box: two names that are the same but for part words ("Modul", "Core", "Engine", "System", "Tool"; also as the end of a compound) or that sound alike (`terms::phonetic`) with at most a third of the letters different and the same digits; `find()` uses that too, and after every run boxes like that are joined (the older stays; never a person and a system, never two different first names, never two boxes the user named).
- The shown spelling wins: the meeting's vocabulary (`terms::vocabulary` of the screens, photos, notes and goal) gives the spellings; a name heard one letter off one of them (four letters on, same first letter), sounding like it, or a mishearing of a written-out name as the term check finds them (`terms::Matcher`: "Tego Modul" → "Teegoo Modul") takes it ("Ecard Modul" → "ECAD Modul"), the heard one kept as another name.
- A box needs more than one screen: a name cited from a screen line that was never said (also as heard another way) and is on fewer than two screens stays a hidden candidate, and a flow can't bring such a candidate in; photos are exempt (the user chose them). Names with an underscore or a lone lower-case letter between words are OCR garbage, never boxes.
- Things the systems describe (machines, plants, vehicles, their parts, product types, a demo's example records) are "data or document" in the map's and the tidy-up's instructions.
- Language pinned: the user prompt ends with "Write in <language>.", and a fact, open point, answer or flow whose little words are clearly English in a German meeting (or the other way round) is dropped. Before, the English example and English slides made a German meeting's map half English, with the same open point in both languages.
- A flow that the cited line says is left out ("die Preise vorher löschen", "without the prices") is no flow.
- Last look: when the meeting stops, after the last run, one more call reads the screens that showed the most boxes at once (an overview slide, without the window chrome; at most two that differ), the names on the call's video tiles (`names::on_screen`: on three frames or more, from every frame read, as the screens' text leaves the tiles out; else names on most screens), and the spoken turns of the whole meeting that name two boxes and say something moves (cut to the sentences naming a box), and may add flows and the people, teams or roles they show (no facts, no open points; a flow's two ends must be in its own line, as the lines come from all over the meeting).
- Speed (the map runs ~14 s each in the meeting's replay, with the live questions on the same model): the instructions no longer change when a screen comes in (the screen sentence is always there), the user prompt puts what changes least first (boxes, removed names, notes) and what changes every run last (facts of the boxes the talk names, candidates, talk), the earlier lines are cut to their last 900 characters, and a screen shows only the rows no screen before showed (OCR jitter of the same slide made a new visual every 10 s; rows alike by letter pairs ≥ 0.7 count as shown), at most 700 characters a screen and 1,000 a run.
